Website support plans

Six parts of a maintenance plan that keep a site working between projects, so small faults are found by us rather than by a customer who gives up and leaves.

Updates applied and verified

WordPress maintenance covering core, plugins, themes and libraries on a schedule, with key pages and forms checked afterwards, because an update that breaks checkout is not an improvement.

Backups that are restore tested

Website backups run on an agreed frequency and get restored to a test environment, because an untested backup is only a hope you discover is empty at the worst moment.

Uptime monitoring and alerts

Uptime monitoring checks your site from outside your office at regular intervals, raising an alert when a page goes down, slows badly or starts returning errors.

Security patching and hardening

Security patching for known vulnerabilities, with login hardening, file permissions and certificate renewals tracked, so nothing lapses quietly over a long weekend.

Content changes without the wait

New staff bios, revised prices, a seasonal banner or an extra service page handled on request, so the site describes what you actually sell this month.

Reporting a manager can read

A plain summary each period: what was updated, what broke and was fixed, what the monitoring saw, and the one or two items that need your decision.

Why clients keep a plan

Updates are applied deliberately and verified afterwards, rather than left to run overnight on their own and discovered broken by a customer on Monday morning.

Backups get restored to a test location regularly, because a backup nobody has ever restored is an assumption rather than a safety net you can rely on.

There is a named way to reach us and an agreed order of priority, so an urgent fault does not sit behind somebody's routine request to swap a photo.

Monitoring and reporting arrive in plain English, so a manager can see what happened to the website without first translating a technical log file.

Common questions

What happens when our site goes down?

Monitoring alerts us, rather than you learning about it from an annoyed customer. We check whether the fault sits with the host, a recent change, an expired certificate or the application itself, restore from a tested backup where that is the safest route, and then write up the cause so the same failure does not return quietly.

Do we need a plan if our site rarely changes?

Often yes, for the opposite reason. A site nobody touches is exactly where a plugin vulnerability sits unpatched, a certificate lapses and a form silently stops sending. Maintenance is less about change and more about noticing. If your site is genuinely static and hosted elsewhere, we will say so and suggest a smaller plan.

Can you maintain a site your team did not build?

Usually. We start with an inventory: hosting, domain, certificates, the content system, plugins and who holds each login. Some sites arrive with abandoned code or a platform no longer supported by anyone, and we say that plainly rather than quoting around it. Where maintenance is not viable, we explain what a rebuild would involve instead.

Who is looking after your site?

If nobody can tell you when the last backup was tested, that is the answer. Get in touch and we will review what is in place today.

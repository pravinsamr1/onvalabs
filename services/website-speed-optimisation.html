What we fix

Performance work

Six areas a website performance audit usually turns up, ranked by what they cost a visitor in seconds rather than by how interesting they happen to be to fix.

Core Web Vitals, properly measured

Google's thresholds are plain: LCP under 2.5 seconds, INP under 200 milliseconds, CLS under 0.1, with at least 75 per cent of visits to a page rated good.

Images that stop being the problem

Oversized photos resized, compressed and served in modern formats, with dimensions set in the markup so the layout stops jumping while a hero image finishes loading.

Scripts, tags and third-party code

Tracking tags, chat widgets and plugins audited one at a time, because the script added for a campaign two years ago is often still delaying every single page.

Caching and content delivery

Page, object and browser caching configured properly, with static files served from a content delivery network so returning visitors are not fetching identical assets twice.

Hosting location and latency

Hosting in Sydney data centres shortens the round trip for Australian visitors, which matters most on mobile networks where every extra request adds measurable delay.

Database queries and server time

Slow queries, bloated tables and unindexed lookups traced on the server, since no amount of front-end tuning rescues a page sitting there waiting on the database.

Why this work is different

Every change is measured before and after under the same conditions, so you see what actually moved rather than a claim that the site feels quicker now.

Testing happens on throttled mobile connections instead of office wi-fi, because that is where most Australian visitors meet your website for the first time.

We tell you when a fix is not worth doing. Some gains cost more in ongoing complexity than they ever return in loading time, and you should hear that early.

INP replaced FID in March 2024, so responsiveness is now judged across the whole visit, and we test what happens when people tap rather than only the first paint.

Common questions

Can you guarantee a particular page speed score?

No, and be wary of anyone who does. Scores shift with the test device, the connection and even the tracking tag somebody adds next week. What we commit to is the method: measure first, fix what is genuinely causing delay, then measure again under the same conditions and show you both sets of numbers.

What are Core Web Vitals in plain terms?

Three measures of how a page feels. LCP is how long the main content takes to appear, targeted under 2.5 seconds. INP is how quickly the page reacts when somebody taps, under 200 milliseconds. CLS covers the layout shifting about, under 0.1. At least 75 per cent of visits to a page must be rated good.

Does hosting in Australia really make a difference?

It can, for Australian audiences. Every request travels to the server and back, and distance adds delay that no front-end tuning removes. Sydney data centres shorten that trip and keep data onshore. It is not the whole answer though: a heavy page hosted nearby is still a heavy page, which is why we measure before recommending a move.

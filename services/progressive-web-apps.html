Progressive web app services

Six parts of progressive web app development that decide whether staff and customers across Australia actually install the thing and keep using it, or tap it once and never return.

Installable web app build

Visitors add the app to their home screen straight from the browser. It gets its own icon and opens full screen, with no download and no store account required.

Offline web application support

An offline web application caches the screens and data people need, so a form still opens in a basement car park, a road tunnel or a paddock with one bar of signal.

Push notifications that earn their place

Push notifications for job updates, order status or appointment reminders. Android has supported them in the browser for years; on iPhone the app must be installed to the home screen first.

One codebase across platforms

A cross platform web app runs on Android, iOS and desktop from one codebase, so a change to a form is written once rather than three times and tested three ways.

When a native app wins

Deep hardware access, background location, Bluetooth peripherals and app store distribution still favour native. We map your requirements against what browsers support before anyone writes code.

Speed on real connections

Built towards Core Web Vitals: LCP under 2.5 seconds, INP under 200 milliseconds and CLS under 0.1, tested on mobile data rather than on office wi-fi.

Common questions

Is a progressive web app as good as a native app?

For many business tools, yes. For some things, no. A progressive web app installs from the browser, works offline and sends notifications, which covers most portals, booking tools and field apps. Native still wins for deep hardware access, background location tracking and Bluetooth devices. We work through your actual requirements before recommending either one.

Do progressive web apps work properly on iPhone?

Partly. Apple supports the core of the standard in Safari, so an installable web app runs on iOS, but it supports less of it than Android does and the gaps shift between releases. Push notifications on iPhone require the user to install the app to the home screen first. We confirm what your iOS audience gets before building.

Can a progressive web app be listed in the app stores?

Sometimes, using a wrapper, though store policies change and we will not promise acceptance. The more useful point is that you may not need to. People install an installable web app straight from your website, updates ship without a review queue, and nothing stands between a fix and the person waiting on it.
